# lib/core/

Cross-feature, reusable code only. Nothing here imports from `lib/features/`.

- **`theme/`** — design tokens extracted from Figma: `AppColors` (colors), `AppTextStyles` (typography, `GoogleFonts.kanit` throughout for Thai-glyph coverage — see the note in `app_text_styles.dart`). Both are `abstract final class`es with `static const`/`static final` fields, grouped by feature with `// --- Feature ---` section comments as they're added.
- **`design_system/`** — layout tokens: `AppSpacing` (gaps/padding/margins), `AppRadius` (corner radii), `AppDimens` (icon/button/avatar sizes, `posterCardAspectRatio`). Same convention as `theme/`: `abstract final class`, private constructor (`AppSpacing._()`), `static const double` fields. Kept separate from `theme/`'s `AppColors`/`AppTextStyles` (color/typography) rather than folded in, since it's a distinct token category; a new color needing to be shared across features still goes in `theme/app_colors.dart`, not here.
- **`strings/`** — `AppStrings`, centralizing UI copy the same way `theme/` centralizes design tokens. Same convention: `abstract final class`, `static const String` fields, feature-prefixed names (`onboardingNextButton`, `authSubmitLogin`, `homeSectionAllPosters`, ...), section comments per feature. Genuinely shared wording (app name, the Thai "coming soon" message) gets one constant reused across features; text that only coincidentally matches gets its own separate constant — don't force-share across unrelated features just because two strings read the same.
- **`assets/`** — `AppImages`, centralizing image asset paths the same way `theme/` centralizes design tokens and `strings/` centralizes copy. Same convention: `abstract final class`, `static const String` fields, unlabeled block for paths shared across 2+ features, `// --- Feature ---` section comments per feature. **Every `SvgPicture.asset(...)`/`Image.asset(...)` call must reference a named constant here — never a literal `'assets/images/...'` string.** When adding a new asset file, add its constant here in the same change.
- **`error/`** — shared domain exception types (`AuthException`, `AuthCancelledException`, `CatalogException`). Data-layer repository impls map SDK-specific exceptions (`FirebaseAuthException`, `DioException`, etc.) into these before they cross into `domain/`.
- **`catalog/`** — cross-feature catalog vocabulary with no Flutter import, so `domain/` layers can depend on it without violating "domain never imports Flutter." `poster_condition_grade.dart`: the `PosterConditionGrade` enum (ADR-0003's 8-level scale, declaration order = meaning — never reorder) plus `label`/`thaiDescription`/`scalePosition`/`apiValue` and `posterConditionGradeFromApi()`. Lives here (not under `features/poster/domain/`) specifically so `core/widgets/condition_grade_indicator.dart` can be typed against it — SCR-03/04/05/11 all reuse the same widget (ADR-0005 §D4), and `core/` cannot import `features/`. `poster_type.dart` · `release_region.dart` · `size_format.dart` · `restoration_status.dart` (added ADR-0011, SCR-05 "แสดงฟิลด์ใหม่") — same shape as `poster_condition_grade.dart` (enum + `label`/`apiValue` extension + `<x>FromApi(String?)` returning `null` for an unrecognized value), one file per enum, also here (not `features/poster/`) so the not-yet-built SCR-04 filter can reuse them. 🔴 `release_region.dart`'s `UNKNOWN` parses to `ReleaseRegion.unknown`, **not** `null` — ADR-0009 §D2 requires `NULL` ("nobody checked") and `UNKNOWN` ("checked, couldn't tell") to stay distinguishable all the way to the UI; the other three enums' `UNKNOWN`/`NONE` members follow the same "still a real value, not a null substitute" rule.
- **`config/`** — build-environment resolution: `Environment` enum, `environmentProvider`, `firebase_options_selector.dart` (picks between `lib/firebase_options_{sit,uat,production}.dart`), `api_base_url_resolver.dart` (`apiBaseUrlFor(Environment)` — `posternung-backend` base URL per environment, overridable via `--dart-define=API_BASE_URL=...`). **Never include `/api/v1` in a value here** — `BackendAuthDataSource` already prefixes every call with it. SIT's default is a developer LAN IP pointing at a locally-run backend (no SIT deployment exists), which is why plain HTTP is opted into for debug/profile builds only — see `docs/environments-setup.md` §6 for the full picture and the Android/iOS cleartext wiring.
- **`network/`** — `api_client.dart`: `dioProvider`, a `Provider<Dio>` reading `environmentProvider` and `apiBaseUrlFor` to build the shared `posternung-backend` HTTP client (wire real endpoints through this client rather than creating a second `Dio` instance). Both this client and the refresh client below share `_baseOptions()`, which sets `connectTimeout`/`sendTimeout`/`receiveTimeout` — Dio's own default is to wait forever, so without this a stalled connection would hang the calling screen indefinitely rather than fail; a timeout surfaces identically to any other transport failure (`AuthException(code: 'network_error')` via `BackendAuthDataSource._guard`). `AuthInterceptor` (from `auth_interceptor.dart`) is attached first — it auto-attaches `Authorization: Bearer <token>` from `TokenStorage` to every request that doesn't already have one or set `options.extra['skipAuth'] = true`, and on a 401 transparently refreshes via a second, bare `Dio` (`_refreshDioProvider`, no interceptors — refreshing must never recurse back through this same interceptor) and retries the original request. It's a `QueuedInterceptor`, not `InterceptorsWrapper`: Dio serializes one interceptor instance's `onError` calls, so concurrent 401s don't each fire their own refresh — see the class doc comment in `auth_interceptor.dart` for exactly how. If a request still fails after that (refresh token missing/rejected), it calls `session_expiry.dart`'s `sessionExpiryProvider.notifier.markExpired()` — a plain bump counter, since `core/` can't import `features/auth/` to clear the session directly; `BackendSessionNotifier` listens to it and reacts the same as an explicit sign-out. In debug builds only (`kDebugMode`) `PrettyDioLogger` is added last, so it logs the final outgoing headers — stripped from every release build. `token_storage.dart`: `TokenStorage` (+ `tokenStorageProvider`), a `flutter_secure_storage` wrapper persisting the backend JWT session (access + refresh).
- **`widgets/`** — generic reusable widgets used by 2+ features, e.g. `AppGradientBackground` (used by onboarding, login, and home). `app_status_view.dart`'s `AppStatusView` — the single screen-level "nothing to show here" block (icon + title + body + optional CTA, `AppStatusTone.error`/`neutral`), used by home's error/empty states and poster's error/not-found states. **Build new empty/error/not-found states on this, not by hand** — the four it replaced had drifted onto `authCardHeading` (an auth *page* title) and left their buttons with no `AppTextStyles` at all, so the CTA label rendered in the `ThemeData` default (Roboto, seed-purple) against a warm dark background. Its own typography lives in `theme/app_text_styles.dart`'s `statusTitle`/`statusBody`/`statusActionLabel`, and the icon halo tints in `AppColors.accentRedSoft`/`accentSoft`. `condition_grade_indicator.dart`'s `ConditionGradeIndicator` — the tappable "Label (n/8)" badge mandated by ADR-0003, built on `core/catalog/poster_condition_grade.dart`; a `null` grade renders a plain, non-tappable "ไม่ระบุสภาพ" status badge instead of a fake grade — never `SizedBox.shrink()`, since every call site pairs this with a price and hiding it would leave the price floating with no condition at all (BR-05). `condition_grade_guide_sheet.dart`'s `showConditionGradeGuideSheet()` — the modal bottom sheet it opens, listing all 8 grades with the current one highlighted; kept as a standalone function so a future full `SCR-11` page can call it directly instead of duplicating the content.
- **`utils/`** — pure, testable extension/formatter/validator functions with no Flutter or Firebase imports. `thai_phone_number.dart`'s `thaiMobileToE164` is the first: normalizes what a user typed in the login screen's phone field (with or without a leading `0`, with or without separators) into the E.164 form Firebase requires.
