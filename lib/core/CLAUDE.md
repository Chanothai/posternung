# lib/core/

Cross-feature, reusable code only. Nothing here imports from `lib/features/` — **with exactly one deliberate exception, `router/`**, which is the composition root for screens and therefore has to name them. The rule holds for every other subfolder, and `router/` earns the exception the same way `main.dart` does: something has to know the whole app, and ADR-0018 D3 chose one place for it rather than a path constant per feature. Nothing in `router/` is imported *by* the feature code it names except `app_routes.dart` and `app_navigation.dart`, which name no widgets at all.

- **`theme/`** — design tokens extracted from Figma: `AppColors` (colors), `AppTextStyles` (typography, `GoogleFonts.kanit` throughout for Thai-glyph coverage — see the note in `app_text_styles.dart`). Both are `abstract final class`es with `static const`/`static final` fields, grouped by feature with `// --- Feature ---` section comments as they're added.
- **`design_system/`** — layout tokens: `AppSpacing` (gaps/padding/margins), `AppRadius` (corner radii), `AppDimens` (icon/button/avatar sizes, `posterCardAspectRatio`). Same convention as `theme/`: `abstract final class`, private constructor (`AppSpacing._()`), `static const double` fields. Kept separate from `theme/`'s `AppColors`/`AppTextStyles` (color/typography) rather than folded in, since it's a distinct token category; a new color needing to be shared across features still goes in `theme/app_colors.dart`, not here.
- **`strings/`** — `AppStrings`, centralizing UI copy the same way `theme/` centralizes design tokens. Same convention: `abstract final class`, `static const String` fields, feature-prefixed names (`onboardingNextButton`, `authSubmitLogin`, `homeSectionAllPosters`, ...), section comments per feature. Genuinely shared wording (app name, the Thai "coming soon" message) gets one constant reused across features; text that only coincidentally matches gets its own separate constant — don't force-share across unrelated features just because two strings read the same.
- **`assets/`** — `AppImages`, centralizing image asset paths the same way `theme/` centralizes design tokens and `strings/` centralizes copy. Same convention: `abstract final class`, `static const String` fields, unlabeled block for paths shared across 2+ features, `// --- Feature ---` section comments per feature. **Every `SvgPicture.asset(...)`/`Image.asset(...)` call must reference a named constant here — never a literal `'assets/images/...'` string.** When adding a new asset file, add its constant here in the same change.
- **`error/`** — shared domain exception types (`AuthException`, `AuthCancelledException`, `CatalogException`) plus the mapper algorithm that turns one into what a screen shows. Data-layer repository impls map SDK-specific exceptions (`FirebaseAuthException`, `DioException`, etc.) into these before they cross into `domain/`. Since ADR-0017, `AuthException`/`CatalogException` are `code` (required, a fixed string — never composed from `runtimeType`) + `displayMessage` (nullable) + `debugDetail` (nullable, **never rendered** — reaches the world only via a `kDebugMode`-guarded log line). 🔴 **As of Amendment 1, `displayMessage` isn't a parameter of either class's public constructor at all** — the only way to populate it is `AuthException.fromEnvelope`/`CatalogException.fromEnvelope`, which take a `BackendErrorEnvelope` (`backend_envelope.dart`) that itself can only have come from `backendErrorEnvelopeOf(DioException)`. `BackendErrorEnvelope`'s own constructor is private and lives in that same file, so nothing outside it can fabricate a look-alike value (a record shape was rejected for exactly this reason — see the class doc comment). This file depending on `package:dio` is a deliberate, narrow exception to "domain doesn't depend on Dio": the dependency stays inside `core/error/` and never reaches `presentation/` through either exception class's public surface. `error_display.dart`'s `resolveErrorDisplay()` is the one allowed algorithm for turning `code`/`displayMessage` into a display string (an allowlist: code → feature's own Thai table → `displayMessage` → static fallback, in that fixed order — see its doc comment) — it lives here because both `AuthException` and `CatalogException` need the identical three-step logic, but each feature owns its own `code`→Thai table next to its own screens (`auth/presentation/auth_error_display.dart`'s `_authMessages`, `poster/presentation/catalog_error_display.dart`'s `_catalogMessages`), per the feature-first rule in root `CLAUDE.md`. `debug_log.dart`'s **`logDebugDetail(value, source:)`** is the only sanctioned way `debugDetail` ever leaves the app (D7): it logs under a `kDebugMode` guard and hands the same value back, so the guard lives *inside* the helper and cannot be forgotten at a call site. Every data-layer `throw` that populates `debugDetail` wraps it in this itself — neither exception constructor calls it on the caller's behalf (Amendment 1 OD-A) — 🔴 **there is no second way**; hand-rolling `if (kDebugMode) developer.log(...)` next to a bare `debugDetail:` is what the source scan in `test/core/error_message_safety_test.dart` rejects. Call it from `data/` only — the same scan bans it elsewhere, because the D10 ban on the token `debugDetail` under `presentation/` is case-sensitive and `logDebugDetail` slips past it.
- **`catalog/`** — cross-feature catalog vocabulary with no Flutter import, so `domain/` layers can depend on it without violating "domain never imports Flutter." `poster_condition_grade.dart`: the `PosterConditionGrade` enum (ADR-0003's 8-level scale, declaration order = meaning — never reorder) plus `label`/`thaiDescription`/`scalePosition`/`apiValue` and `posterConditionGradeFromApi()`. Lives here (not under `features/poster/domain/`) specifically so `core/widgets/condition_grade_indicator.dart` can be typed against it — SCR-03/04/05/11 all reuse the same widget (ADR-0005 §D4), and `core/` cannot import `features/`. `poster_type.dart` · `release_region.dart` · `size_format.dart` · `restoration_status.dart` (added ADR-0011, SCR-05 "แสดงฟิลด์ใหม่") — same shape as `poster_condition_grade.dart` (enum + `label`/`apiValue` extension + `<x>FromApi(String?)` returning `null` for an unrecognized value), one file per enum, also here (not `features/poster/`) so the not-yet-built SCR-04 filter can reuse them. 🔴 `release_region.dart`'s `UNKNOWN` parses to `ReleaseRegion.unknown`, **not** `null` — ADR-0009 §D2 requires `NULL` ("nobody checked") and `UNKNOWN` ("checked, couldn't tell") to stay distinguishable all the way to the UI; the other three enums' `UNKNOWN`/`NONE` members follow the same "still a real value, not a null substitute" rule.
- **`config/`** — build-environment resolution: `Environment` enum, `environmentProvider`, `firebase_options_selector.dart` (picks between `lib/firebase_options_{sit,uat,production}.dart`), `api_base_url_resolver.dart` (`apiBaseUrlFor(Environment)` — `posternung-backend` base URL per environment, overridable via `--dart-define=API_BASE_URL=...`). **Never include `/api/v1` in a value here** — `BackendAuthDataSource` already prefixes every call with it. SIT's default is a developer LAN IP pointing at a locally-run backend (no SIT deployment exists), which is why plain HTTP is opted into for debug/profile builds only — see `docs/environments-setup.md` §6 for the full picture and the Android/iOS cleartext wiring.
- **`network/`** — `api_client.dart`: `dioProvider`, a `Provider<Dio>` reading `environmentProvider` and `apiBaseUrlFor` to build the shared `posternung-backend` HTTP client (wire real endpoints through this client rather than creating a second `Dio` instance). Both this client and the refresh client below share `_baseOptions()`, which sets `connectTimeout`/`sendTimeout`/`receiveTimeout` — Dio's own default is to wait forever, so without this a stalled connection would hang the calling screen indefinitely rather than fail; a timeout surfaces identically to any other transport failure (`AuthException(code: 'network_error')` via `BackendAuthDataSource._guard`). `AuthInterceptor` (from `auth_interceptor.dart`) is attached first — it auto-attaches `Authorization: Bearer <token>` from `TokenStorage` to every request that doesn't already have one or set `options.extra['skipAuth'] = true`, and on a 401 transparently refreshes via a second, bare `Dio` (`_refreshDioProvider`, no interceptors — refreshing must never recurse back through this same interceptor) and retries the original request. It's a `QueuedInterceptor`, not `InterceptorsWrapper`: Dio serializes one interceptor instance's `onError` calls, so concurrent 401s don't each fire their own refresh — see the class doc comment in `auth_interceptor.dart` for exactly how. If a request still fails after that (refresh token missing/rejected), it calls `session_expiry.dart`'s `sessionExpiryProvider.notifier.markExpired()` — a plain bump counter, since `core/` can't import `features/auth/` to clear the session directly; `BackendSessionNotifier` listens to it and reacts the same as an explicit sign-out. In debug builds only (`kDebugMode`) `PrettyDioLogger` is added last, logging method/URL/status/timing for every request — headers and bodies are all off (`security-baseline` §2 / ADR-0017 OD-2: every token this app has travels in a request or response body at some point, not just the `Authorization` header, so body logging is off app-wide rather than per-path — see the doc comment at the `PrettyDioLogger(...)` call for the one known residual gap in that). Stripped entirely from every release build regardless. `token_storage.dart`: `TokenStorage` (+ `tokenStorageProvider`), a `flutter_secure_storage` wrapper persisting the backend JWT session (access + refresh).
- **`widgets/`** — generic reusable widgets used by 2+ features, e.g. `AppGradientBackground` (used by onboarding, login, and home). `app_status_view.dart`'s `AppStatusView` — the single screen-level "nothing to show here" block (icon + title + body + optional CTA, `AppStatusTone.error`/`neutral`), used by home's error/empty states and poster's error/not-found states. **Build new empty/error/not-found states on this, not by hand** — the four it replaced had drifted onto `authCardHeading` (an auth *page* title) and left their buttons with no `AppTextStyles` at all, so the CTA label rendered in the `ThemeData` default (Roboto, seed-purple) against a warm dark background. Its own typography lives in `theme/app_text_styles.dart`'s `statusTitle`/`statusBody`/`statusActionLabel`, and the icon halo tints in `AppColors.accentRedSoft`/`accentSoft`. `condition_grade_indicator.dart`'s `ConditionGradeIndicator` — the tappable "Label (n/8)" badge mandated by ADR-0003, built on `core/catalog/poster_condition_grade.dart`; a `null` grade renders a plain, non-tappable "ไม่ระบุสภาพ" status badge instead of a fake grade — never `SizedBox.shrink()`, since every call site pairs this with a price and hiding it would leave the price floating with no condition at all (BR-05). `condition_grade_guide_sheet.dart`'s `showConditionGradeGuideSheet()` — the modal bottom sheet it opens, listing all 8 grades with the current one highlighted; kept as a standalone function so a future full `SCR-11` page can call it directly instead of duplicating the content.
- **`router/`** — the app's route table (ADR-0018). `app_routes.dart`'s `AppRoutes`: every path pattern and route name as `static const`, plus `allPaths`/`allNames` and the `posterDetail(id)` builder. Centralised here rather than declared next to each feature — the repo's usual rule for providers — because **uniqueness is a property of the set, not of any member**, and `test/core/router/app_router_test.dart` can only assert on a set that exists somewhere (ADR-0018 D3). `app_router.dart`: the `appRoutes` list of `GoRoute`s and the `routerProvider` that `main.dart`'s `MaterialApp.router` reads; `appRoutes` is public so tests can stand a router up over the *real* table instead of pumping `MaterialApp(home: X)`, which stays green no matter what the table says. 🔴 It holds **no `GoRouterState.extra` read at all** — ADR-0018 **Amendment 2 (A2-D2)** moved the OTP flow's state to `otpFlowProvider` and left `/otp` carrying no arguments, because `extra` is JSON-encoded into route restoration state and a value go_router cannot encode becomes `null` on every `refresh()`. `route_state_guard.dart`'s `requireRouteState<T>()` is the one door a route goes through when it needs state it cannot render without, and `no_imperative_navigation_test.dart` asserts the count of `.extra` reads in go_router-importing files is **zero**, not that it is one. `app_navigation.dart`: `context.popOrGoHome()`, used instead of a bare `pop()` because `go_router` throws when the current route is the only one on the stack. Widget tests reach all of this through `test/support/router_harness.dart` — the one place in `test/` that does not mirror `lib/`, because it is a harness rather than a subject. 🔴 **`Navigator` and `MaterialPageRoute` must not appear in `lib/` at all** — `test/core/router/no_imperative_navigation_test.dart` enforces it with an empty allowlist, including inside modal sheets (verified: `context.pop()` there closes the sheet, not the page under it). 🔴 A route table is **not** deep linking — that needs native config in `android/`/`ios/` which this round deliberately did not touch (ADR-0018 D5, deferred to INF-15).
- **`utils/`** — pure, testable extension/formatter/validator functions with no Flutter or Firebase imports. `thai_phone_number.dart`'s `thaiMobileToE164` is the first: normalizes what a user typed in the login screen's phone field (with or without a leading `0`, with or without separators) into the E.164 form Firebase requires.
